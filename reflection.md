Lab 5: Static Code Analysis — Reflection

1. What is static code analysis, and why is it important?

Static code analysis examines source code without executing the program. Tools such as Pylint, Bandit, and Flake8 identify potential bugs, security risks, and style violations. It helps developers improve code quality, readability, security, and maintainability.

2. What issues did you identify in the program?

The analysis identified potential problems such as a mutable default argument, broad exception handling, insecure temporary-file creation, subprocess-related security warnings, and formatting violations. These findings helped identify areas where the code could be made safer and easier to maintain.

3. How did you fix the issues, and how did you verify the fixes?

I reviewed the reports generated by Pylint, Bandit, and Flake8. I corrected the identified issues and ran the tools again to generate new reports. I also checked that the program continued to produce the expected output after the changes.

4. How does static code analysis improve software quality?

Static code analysis helps detect potential problems early, before they cause failures in production. It encourages consistent coding practices, improves security, reduces maintenance effort, and makes code easier for other developers to understand and review.
